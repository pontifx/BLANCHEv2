BLANCHE Site Search and advanced search suite change trace
Created: 2026-09-17 15:18:47 -07:00

Requested behavior
- Select Google by default while retaining the other engines as explicit options.
- Let an operator pick, scan/highlight, or supply the target site's search endpoint.
- Run the portable advanced-operator templates with an optional keyword list.
- Summarize direct page markers separately from observed result behavior.

Implemented
- Fresh/reset Search drafts select Google only. Valid persisted engine choices and built-in reviewed multi-engine profiles remain intact.
- Focus terms accept newline, comma, or semicolon delimiters; normalize, deduplicate, and enforce bounded word, character, term, and submission limits.
- Query caps distribute probes round robin across focus terms and report complete/partial/omitted coverage.
- Site Search binds every portable probe once to the selected search page host and omits the redundant site: operator.
- Added top-frame page scan, candidate highlight, and interactive field picker with Escape, timeout, replacement, and cleanup handling.
- Aligned picker and discovery ranking/limits and protected overlapping highlight timers.
- Added bounded possible provider markers for Google Programmable Search, Algolia, Elastic/App Search, Azure AI Search, Solr, Typesense, Meilisearch, and Swiftype. The UI labels them as page-level hints with medium confidence.
- Added aggregate result/zero-result/manual/failed behavior fingerprints by category and operator. Result behavior does not name a backend.
- Provider markers persist in the sanitized task surface snapshot; selectors, hidden form data, credentials, fragments, old query values, and sensitive URL parameters do not.
- Added a focused browser smoke command: npm run smoke:site-search.
- Fixed the generic search-tab load race by registering the completion listener before the follow-up status check.
- Retained disclosure state and target URL control behavior from the previous change.
